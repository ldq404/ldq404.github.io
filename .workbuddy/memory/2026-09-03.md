## mark 默认色改为蓝色 → 重构为 CSS 变量

用户要求 `<mark>`（不带 class）默认底色从黄色改为蓝色，随后反馈"改默认会弄丢黄色"，最终定稿方案（用户偏好：**默认色要随时可改，具体颜色用 class 指定**）：
- `macos.css`：`.markdown-section mark` 默认背景改为 `var(--mark-bg, rgba(0,122,255,.22))` —— 默认色走 CSS 变量，用户想换默认色只需在文件末尾覆盖 `--mark-bg` 一处。
- **补回 `mark.yellow`**（原默认黄 `rgba(255,214,10,.35)` 移入 class），现共 7 个 class：yellow/red/orange/green/blue/purple/gray。blue 类保留向后兼容（与默认同值）。
- `docsify-theme/README.md` / `DEMO.md` 同步：示例改为「默认色 + 7 class」全列表，README 特性栏与自定义节说明 `--mark-bg` 变量用法。

`macos.css` mark 默认 `padding: 0 3px` → `padding: 1.5px 1px`（垂直留白增加、水平收紧），随即用户改口 → 最终定稿 `padding: 0.5px 2px`（轻量垂直内边距 + 中等水平）。

## 划重点两件套：mark 涂色 + line 波浪线（新增）

用户语义定稿：**`<mark>` = 涂色（水彩笔/荧光笔，背景染色），`<line>` = 划线（文字下波浪线，不遮字）**，两套都支持 7 色 class（yellow/red/orange/green/blue/purple/gray），默认色走容器级 CSS 变量（`--mark-bg` 涂色底、`--line-color` 波浪线色），随时可改。
- `macos.css`：`.markdown-section` 新增 `--mark-bg`（默认 `rgba(0,122,255,.22)`）与 `--line-color`（默认 `#007aff`）变量；`.markdown-section line` 用 `text-decoration-style: wavy` + `text-decoration-color`（含 solid 兜底给老浏览器），波浪线用实色系（#ffcc00/#34c759/#007aff/#ff9500/#ff3b30/#af52de/#8e8e93，比 mark 淡底更醒目）。
- `<line>` 是 HTML 非标准标签，实测 marked v4.3.0 会原样透传 `<line class="...">`（node require lib/marked.min.js 验证），与 `<mark>` 行为一致 → 可行。
- line 波浪线微调定稿：`text-decoration-thickness: 1px; text-underline-offset: 0.2em`（em 随字号缩放；此前试过 2px/3px 定值）。
- **line 内嵌 `<code>` 波浪线断裂问题（技术结论，已探明机制）**：
  - 现象：`<line>` 的 wavy 在遇到行内 `<code>` 时，code 左右 padding/margin 空白区无线 → 视觉断开。
  - 根因：`text-decoration` 只画在**文字 run** 上，padding/margin 是纯空白无 run → 无论父线传播还是子元素自己画，空白区都无线，**CSS 无法让 text-decoration 补上空白区**（无解，非 bug）。
  - 踩过的坑：① `text-decoration: inherit` 让 code 自己画 → 无效且 code 文字区叠画两层（颜色变深，用户实测确认）；② 取消 line 内 code 背景/padding → **用户否决**（偷懒方案，code 样式必须保留，实测 background 不干扰）。
  - **最终结论（用户拍板 2026-09-03）：接受现状，不追求波浪线穿过 code 留白**。CSS 保持干净：无任何 `line code` 特殊规则，code 走全局样式，父线单层传播。终极方案（未采用）：波浪线改 SVG 背景平铺、不依赖 text-decoration。
